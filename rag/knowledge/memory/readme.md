# Memory

本目录封装对话记忆在 RAG 层的读取、选择和写入策略。

包含三层记忆：

- 短期窗口：保留最近若干轮原始消息；
- 滚动摘要：超过窗口后，由摘要流程压缩较早对话；
- 结构化长期记忆：保存稳定偏好、实体、项目背景和明确事实。

应该定义记忆抽取、更新、去重、过期、召回和隐私规则。滚动摘要由 AI 生成时必须保留来源消息范围、Prompt 版本、摘要版本和前一摘要 ID，不能把模型推断自动当成用户事实。

滚动摘要不能原地覆盖：新摘要基于旧摘要加尚未覆盖的消息生成一条新版本，旧版本标记为 superseded。Conversation 使用 `version/expected_version` 乐观更新当前摘要指针；并发冲突时放弃过期结果或有限次重新读取后重试。

结构化长期记忆采用“逻辑 Upsert、物理追加 Revision”：相同 memory_key 的新事实成为 active，旧版本标记为 superseded；用户明确否定的版本标记为 retracted。无法确认替代关系时保留冲突候选并请求用户确认。

SQL 保存持久记忆和消息，向量索引用于长期记忆召回，Redis 只适合短期缓存。LangGraph Checkpoint 是运行状态恢复机制，不等同于长期记忆。
